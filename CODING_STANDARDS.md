## Code and Dev Flow

The code base is about 50% hand-coded and 50% agentic-tool-augmented (Claude Code with typically Opus 4.6 and Fable for these latest features, and a mix of local models for super basic workflow and devops automation). About the same split I employ in all software work I do professionally. Every line of code has been iteratively revised and improved on the fly by myself, and then hand-reviewed again before merging, whether it was generated or not.

A little more detail: When agentic tooling is used, I am at the seat with my architect/lead hat on directing every prompt and doing manual testing on everything produced against multiple test environments and UniFi sites. I hand-select which model to use for each problem, and often gut and rewrite / reorganize things myself if I don't like the end result. At least up until v2.7.2, I've been working about 12-16 hours a day on Network Optimizer, often 7 days a week, since November 2025. This is not a one-shot AI-written project, and you can tell from the commit history of 3300+ mostly post-squash commits. Every feature branch, every PR, every single release of 260+ releases so far, has been hand-orchestrated by me w/ Claude Code as a force multiplier.

There are no automated AI loops or agents in this project or repo. When you submit a GitHub Issue, that's me reviewing it and replying every time. Basically, I use AI exactly as I do in an enterprise team setting to automate my dev workflow and to type code and refactor faster than I physically can, and hold myself to an extreme level of integrity and accountability around what I produce using its assistance. There's no replacement for having an experienced engineer at the helm of a project like this.

This has been a painstaking process, and I'm 2500+ hours deep on Network Optimizer as it looks today, and 1500+ hrs into the R\&D, reverse engineering, and vetting of all of the performance tweaks, security checks, and monitoring tools from my personal stack that have been folded into NO.

Contributors are free to use whatever tools they would like, but I can pretty well sniff out vibe-coded slop vs properly-engineered deliberate solutions. The gap is closing with newer models like Fable, but it's usually pretty obvious for me, and I will not hesitate to tear a PR apart (as friendly as possible) if it has deficiencies.

## Quality

I take a lot of pride in all projects and products I code, whether it's down to the pixel-level placement of UI elements in responsive layout, or anal retentiveness about code quality standards. But like any large project, NO has some tech debt, and most of it is documented in the [TODO.md](TODO.md) in the repo or in TODO comments in the code base.

Code should be clean, easy-to-read, and inclusive of useful but not superfluous comments. It should employ good design patterns where appropriate without being over-engineered, and reuse existing common code and styles wherever possible. Rule of thumb, if logic is used more than 2 places, it needs to be in a common utility or otherwise abstracted.

## Submitting Bugs and Issues on GitHub

I understand using LLMs as a translator, but I don't mind rough English at all. If you're engaging with me seriously, and want things done on this project, I prefer bug report summaries and discussions to be hand-written. If an LLM is pointed at an observed issue in NO and the repo, it often cannot see the forest from the trees, especially without my private research notes and SOPs. It can and will confidently misdiagnose things I've already done intentionally, or even documented in and outside of the codebase. Unless you give it a ton of context, AI is not a seer. Keep that in mind. The code base is large enough where you'd waste half of your daily tool usage quota just by having it pull context. Just be aware of this context when opening an Issue on here, pure AI bug reports will come across as lazy to me, and I'm less likely to engage and implement features if a proportionate effort hasn't been made to investigate and document what is wrong or what is requested in a new feature, vs what it will take for me to get it done.

I really appreciate all testing, feature requests, and bug reports that are contributed, regardless of AI assistance, but please help me make the process easier by checking your agentic tool use before submitting. If that means feeding a bug report into another agentic tool or model to check the validity and work, sometimes that makes it easy, assuming you don't have the bandwidth to hand-review everything, or have to switch context to something else.

I get it, I see you, and I really love everything people have contributed to the project so far!
